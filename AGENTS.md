# AGENTS.md

## Project Overview
PhenixCode Chat Assistant — a Visual Studio extension (VSIX) providing an AI coding assistant inside VS.
- Extension ID: `ChatAssistantVSIX.9a72f873-133b-4224-b774-e6d9648c420e`
- Version: 1.0, Author: Arman Sahakyan
- Uses Markdig for Markdown parsing and WPF `FlowDocument` for rendering.
- Talks to a local backend service (`http://localhost:<port>/api/...`) that is started/stopped by the extension.

## Build & Run
- Build the solution in Visual Studio (requires VSIX development workload) or via `msbuild`.
- `source.extension.cs` is auto-generated by VSIX Synchronizer — do not edit manually.
- Debugging launches the Experimental Instance of Visual Studio.

## Architecture / Key Files
- `MarkdownFlowDocument.cs` — converts Markdown to a WPF `FlowDocument` (headings, paragraphs, code blocks, quotes, lists, thematic breaks, inline emphasis/links/code). Uses `Markdig` with `UseAdvancedExtensions()`.
- `PhenixCodeCoreService.cs` — core service layer:
  - Global settings: `%APPDATA%/PhenixCode/settings.json` (seeded from embedded `Resources/settings.default.json`).
  - Solution settings: `<solutionDir>/.phenixcode/settings.json`; runtime info in `.phenixcode/info.json` (contains `port`, `pid`, `exec`).
  - Service lifecycle: `InitOnSolutionReady`, `StartProcess`, `ShutdownServiceAsync`, `IsServiceRunning`, `FetchRunningServiceProcess`.
  - API calls: `/api/fim` (fill-in-the-middle), `/api/chat` (streaming SSE-style `data:` lines, terminated by `[DONE]`), `/api/shutdown`.
- `source.extension.cs` — generated VSIX manifest constants.

## Conventions
- Respect the existing file-scoped style: some files use `namespace X { }` blocks with `using` inside the namespace; keep each file's style consistent.
- All user-facing status messages go through `Diag.OutputMsg(...)` or the output pane (`[OUT]`, `[ERR]`, `[System]` prefixes).
- Markdown output is rendered via `VsBrushes.*` resources for theming (ButtonFace, ButtonText, AccentMedium).
- Config reads are defensive: always check for null/empty paths and missing files, log and return empty/default on failure.
- Local service port comes from `info.json` (`port`); the service is launched with `--port 59241` by default.
- Prefer async/await; use `ThreadHelper.JoinableTaskFactory` for VS threading, `.FireAndForget()` for fire-and-forget tasks.

## Gotchas
- `$(SolutionDir)` in settings is replaced with the actual solution path in `SaveToSolutionSettings`.
- `ChatCompletionStreamAsync` currently returns `string.Empty` (result is only surfaced through `onTokenReceived`); `ChatCompletionAsync` returns the accumulated text.
- Do not add "Sources" sections; the host app appends them automatically.
